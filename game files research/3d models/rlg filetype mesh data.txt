Mesh data: section identifier B004

Section header:
0x0: flags?
0x2: identifier B0 04
0x4: length of the section body, it's always equal to the number of meshes times 0x30.
If you want to know how many meshes a .rlg contains, divide this number by 0x30.
From my experience, most .rlg files contain 12 meshes.


Section body:
The section's body is split into many chunks of 0x30 bytes each. One for each mesh.

Each chunk is structured as follows:
0x00 index_start_offset              (UINT32)
0x04 index_format                    (UINT16)
0x06 index_count                     (UINT16)
0x08 vertex_count                    (UINT16)
0x0A unknown
0x0B vertex_attribute_pointer_count  (BYTE)
0x0C unknown                         (UINT32) (this is probably the attribute pointer offset)
0x10 material_hash_id                (UINT32)
0x14 mesh_hash_id                    (UINT32)
0x18 unknown
0x1C unknown 
0x20 material_offset                 (UINT32)
0x24 unknown
0x28 unknown
0x2C unknown



If you need to read any data from the mesh data section, use the following formula to find the location of that data:
( section body start ) + ( 0x30 * number of the mesh ) + offset of the value to look for

For example, we need mesh 5's vetex_count.
Let's pretend our rlg file has a mesh data section body that starts at 0x1000, the formula would be:
0x1000 + ( 0x30 * 5 ) + 0x8 =
0x1000 + 0xF0 + 0x8 =
0x10F8
