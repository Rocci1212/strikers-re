Skeleton data: section identifier B008
This section contains part of the skeleton data, but according to KillzXGaming, "the bones themselves are located in .shier files with parenting information"

Section header: 
0x0: 80 01  I'm starting to think that the "80" at the beginning of the header means that it contains other sections.
0x2: identifier B0 08
0x4: length of the section body, extends to the end of the file


Section body:
Many "bone mesh hashes" sections (B00B) 
A single "bone data" section (B00A)
A single "B00C" section, the purpose of which is unknown








Bone mesh hashes: section identifier B00B. There are multiple instances of this section in a rlg file. One per each mesh.

Section header:
0x0: flags
0x2: identifier B0 0B
0x4: length of the section body, can vary, usually pretty short.
     The length reflects the number of bones used by the mesh (number of bones used) / 4

Section body:
Array of hashes containing the N bones used by the mesh.  (UINT32[N])








Bone data: section identifier B00A

Section header:
0x0: flags
0x2: identifier B0 0A
0x4: length of the section body,
     The length is bone count times 0x44.

Section body:
It's split in chunks of 0x44 bytes each.
Each chunk is associated to a bone.
From my undestanding, this is how each chunk is structured:
0x0: bone hash id  (UINT32)
0x4: matrix        (FLOAT[16])
     Not sure what the matrix is for. I'm a 3d modelling noob, so I wouldn't understand this kind of thing








Unknown section B00C:

Section header:
0x0: flags
0x2: identifier B0 0C
0x4: length of the section body
